מפרט TO-BE — לוגיסטיקה ומשלוחים (LOG). המסמך מכסה את כל 33 התהליכים שב-rules-logistics.html, בלי השמטות ובלי מיזוגים. מה שעובד היום הועתק כפי שהוא. שינינו רק מה שההחלטות המאושרות מחייבות, בכפוף לכלל העל: כל יכולת ופעולה שהמשתמש מקבל היום נשמרות.

החלטות שהוחלו: 40 פריטי LOG שאינם כפולים: FIX 16, HARDEN 6, CONSISTENCY 5, BEHAVIOR 11, SCOPE 2. שני פריטים כפולים הוחלו דרך הפריט הקנוני: LOG-01→ARC-03 (אין fallback בלי טוקן), LOG-08→ARC-21 (מע"מ 18% דרך calcVat, עוסק פטור 0%). החלטות ARC מוזכרות לפי מזהה בלבד: אימות וסשן (ARC-01..ARC-06), טרנזקציות (ARC-11), מיגרציות (ARC-12/ARC-13), לקוח אחד (ARC-14), התראות (ARC-16), זכאות וקטלוג מודולים (ARC-17/ARC-18), מע"מ (ARC-21), אזור זמן (ARC-25), העלאות (ARC-26), XSS (ARC-27), Rate limit (ARC-29), AI (ARC-30), PII (ARC-32), שגיאות (ARC-33), ולידציה (ARC-34), נתיבים (ARC-35).

פריטים שעודכנו (18). בכל אחד: מזהה, למה שונה, והכלל הסופי.

  • LOG-03. למה: מעבר לבדיקת מזהה טאב ו-fail-closed בלי מיגרציה היה חוסם עסקים קיימים (managed_modules ריק או מכיל רק 'logistics'), שהיום עוברים. כלל סופי: כל נתיב ממופה למזהה הטאב שלו ונבדק מול tenant_entitlements. שגיאת DB מחזירה 503. מיגרציה חד-פעמית נותנת לכל עסק קיים את כל טאבי logistics_* שנגישים לו היום. מערך ריק או הערך 'logistics' מתורגמים לכל 11 הטאבים. logistics_rfq נכלל ב-logistics_all.

MANAGER מבצע היום תיקוני סטטוס, ולכן הוא נשאר מורשה. כלל סופי: חשבונית והכנסה נוצרות פעם אחת בלבד, במעבר הראשון ל-delivered/partial, באותה טרנזקציה. יציאה מ-delivered/partial (מנהל בלבד) מבטלת את החשבונית, רושמת תנועה הפוכה ומאפסת את delivered_at.

"ללא נהג" מחזיר הזמנה שנמצאת ב-assigned ל-confirmed. רק רכבים פעילים מוצעים לבחירה. רכב שהביטוח או הטסט שלו פגו מציג אזהרה וחוסם, אלא אם המשתמש מאשר (confirm_expired=true). האישור נרשם ב-audit.

  • LOG-17. למה: חובה לסמן גבייה לפני מסירת הזמנת COD הייתה חוסמת מסירה שבה הלקוח משלם מאוחר יותר. זה בדיוק המצב שמוצג היום כ"להפקדה" או כחוב. כלל סופי: מסירת הזמנת COD בלי סימון גבייה דורשת אישור "נמסר ללא גבייה?". ההזמנה נשארת ברשימת החוב (uncollected). ביטול סימון גבייה מותר ל-ADMIN בלבד, ורק לפני סגירת היום.

אימות, gating מודול ויומן ביקורת לכל נתיבי /api/logistics

מטרה וטריגר
כל נתיבי /api/logistics/*, למעט רשימה ציבורית סגורה, וכל קריאה מסביבת BIZ (business-app.js).
הרשאות
  • authenticate() + requireType('biz'). verifyBizOrLegacy נמחק ואין מצב legacy (ARC-03, שמכסה את LOG-01).
  • groupId נלקח רק מ-req.principal.groupId. אם יש :groupId בנתיב או group_id בגוף והם שונים מהסשן: 403. כל שאילתה לפי :id כוללת AND group_id=$session, ואם לא נמצאה שורה: 404. מזהים מקושרים בגוף (driver_id, vehicle_id, order_id בעצירה, pricing_zone_id, customer_id, route_id) חייבים להיות שייכים לאותו group, אחרת 400 (LOG-02, ARC-04).
  • requireModule(<tab-id>) לפי מיפוי נתיב→טאב (LOG-03 בגרסה המעודכנת, ARC-17): /orders*, /driver-orders → logistics_orders. /drivers* → logistics_drivers. /vehicles* → logistics_vehicles. /pricing*, /rate-cards* → logistics_pricing. /cod* → logistics_cod. /rfq* → logistics_rfq. /routes* → logistics_routes. /orders/:id/tracking-token → logistics_orders או logistics_tracking. /reports → logistics_reports. /customers* → logistics_customers. /invoices* → logistics_invoices. /dashboard → כל טאב logistics_*. שגיאת DB מחזירה 503 (fail-closed).
  • הרשאות פעולה (ARC-06): משתמש תפעול, מנהל ונהג מקושר, כפי שהוגדרו במבוא. ההרשאות המפורטות מופיעות בכל תהליך.
  • רשימה ציבורית (ARC-02): GET /track/:token (דף), GET /api/logistics/track/:token, POST /api/logistics/track/:token/leave-at-door, GET /api/logistics/track-lookup/:groupId (LOG-31), נתיבי הלקוח ל-RFQ לפי טוקן (LOG-27), ו-POST /api/store/leads/:groupId (תחום החנות). כל אלה עם rate limit (ARC-29).
קלט ואימותים
  • בלי טוקן: 401 "נדרשת התחברות". טוקן לא קיים או שפג תוקפו: 401 'token לא תקף' (נשמר). סשן מסוג אחר: 403 'נדרש token מסוג עסקי' (נשמר).
  • משתמש לא active: 401. חשבון frozen/archived: 403 "החשבון מוקפא" (ARC-05).
  • מודול חסר: 403 'גישה למודול זה אינה כלולה בחבילה שלך' (נשמר).
שלבי עיבוד
  1. זיהוי הסשן לפי hash בטבלת sessions, ועדכון last_seen אסינכרוני (כמו היום) (ARC-01).
  2. בדיקת זכאות. ה-cache נשמר 60 שניות (_MOD_CACHE_TTL=60000), ומתבטל במפורש בכל שינוי זכאות (ARC-24).
  3. ה-handler מקבל ctx={principal, groupId}.
  4. middleware יומן הביקורת הגנרי (server.js:121–144) ממשיך לפעול על res.on('finish') לכל POST/PUT/PATCH/DELETE עם 2xx–3xx, עם עד 12 שדות גוף ובלי מפתחות password|token|secret|signature. עכשיו יש תמיד group_id ו-user_id מהסשן, ולכן כל כתיבה לוגיסטית נרשמת (LOG-04).
  5. הנתיבים שיש להם רישום ייעודי לא נרשמים ברישום הגנרי, כדי שלא יהיה רישום כפול. הרשימה מתרחבת מ-orders/:id/status ו-invoices/:id/status ל: assign, failed-attempt, pod, cod, cod/close, DELETE orders/:id, DELETE invoices/:id. כל אחד מהם רושם logBizAction ייעודי עם old/new value (LOG-04).

חישובים

  • total_orders = מספר ההזמנות עם cod_amount>0 ו-scheduled_date=date (כמו היום).
  • total_due ("לגבות") = Σ cod_amount (>0) לפי scheduled_date=date (כמו היום).
  • expected_cash ("נגבה") = Σ cod_amount של הזמנות הנהג שבהן cod_collected ו-toILDate(cod_collected_at)=date (LOG-18).
  • to_deposit ("להפקדה") = expected_cash − סכום שכבר הופקד בסגירה של אותו יום.
  • uncollected ("לא נגבה — חוב לקוח") = Σ cod_amount >0, לא נגבה, status IN ('delivered','partial'). זה המדד שנקרא היום "להפקדה", ועכשיו הוא מוצג בנפרד בשם הנכון.
  • variance = deposited_amount − expected_amount.
