אימות, תפקידים ומידור (BIZ)

שכבת אימות עסקית — verifyBiz / verifyBizOrLegacy / verifyFamilyOrBiz / verifyFamily

מטרה וטריגר
Middleware שרץ לפני כל endpoint עסקי. הטוקן נשלח ע"י הלקוח ב-Authorization: Bearer ${window._bizToken} (business-app.js בכל fetch מאובטח). כל ה-sessions (משפחה ועסק) נשמרים באותה טבלה family_sessions ומובחנים ב-session_type.
תנאים ואימותים
  • verifyBiz (server.js:41914-41948): חסר טוקן → 401 "נדרש token להתחברות עסקית"; טוקן מגובב (_hashToken) ומחופש ב-family_sessions.token_hash; לא נמצא → 401 "פגישה לא תקינה — יש להתחבר מחדש"; expires_at עבר → מחיקה אסינכרונית + 401 "פגישה פגה — יש להתחבר מחדש"; session_type !== 'biz' → 403 "גישה מורשית לעסקים בלבד" (41936). מציב req.bizAuth={groupId,userId,role,employeeRoleType} — role ו-employee_role_type נשלפים מ-users (41941).
  • verifyBizOrLegacy (43056-43086): אם יש טוקן — חייב להיות תקף ומסוג biz (אחרת 403 "נדרש token מסוג עסקי" / 401 "token לא תקף"); מציב fromToken:true (43073). אם אין header כלל — fallback: groupId נלקח מ-req.body.groupId או req.query.groupId, fromToken:false, נרשם console.warn ועובר הלאה (43082-43085). לא מציב role.
  • verifyFamilyOrBiz (43089-43118): מקבל שני סוגי session; מציב req.callerAuth={groupId,userId,type:'business'|'family',role} וגם alias req.bizAuth={groupId,userId,role} (43109) — לכן גם בקשות שעוברות דרכו נרשמות ביומן הביקורת הגלובלי.
  • verifyFamily (41876-41910): לא בודק session_type — טוקן עסקי עובר גם בו. מציב req.familyAuth. ה-BIZ משתמש בו בפועל ל-PUT/DELETE משתמשים ותנועות.
  • כל ה-middlewares מעדכנים last_seen=NOW() אסינכרונית.
שלבי עיבוד
  1. חילוץ טוקן (עם/בלי "Bearer ").
  2. SELECT מ-family_sessions לפי hash.
  3. בדיקת תפוגה וסוג.
  4. UPDATE last_seen (fire&forget).
  5. (verifyBiz/OrBiz) SELECT role מ-users.
תופעות לוואי
Cron יומי מוחק sessions שפגו (server.js:43835-43845, כל 24 שעות).
פערים
  • requireModule נאכף רק כש-fromToken===true, ש-רק verifyBizOrLegacy מציב; לכן מסלול ללא header עוקף את שער המודול לחלוטין (43128) ואף מקבל groupId שרירותי מה-body.
  • verifyFamily מקבל טוקן עסקי (חוסר בדיקת session_type) — מכוון בפועל, אך לא מתועד.
  • endpoints רבים בתחום (timeclock, alerts, sla, shift-templates, team-posts, inbox, chat, surveys, timelog, reports, payroll, licenses, business-settings) הם ללא middleware בכלל — מקבלים groupId/userId מה-body/query/params.
