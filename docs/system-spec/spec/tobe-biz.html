שכבת אימות עסקית — verifyBiz / verifyBizOrLegacy / verifyFamilyOrBiz / verifyFamily

מטרה וטריגר
Middleware שרץ לפני כל endpoint עסקי (default-deny, ARC-02). הלקוח שולח Authorization: Bearer ${window._bizToken} בכל fetch (business-app.js — עטיפת fetch אחת לכל הקריאות, כולל פעולות AI והורדות). הטוקן הוא טוקן סשן אטום (32 בתים אקראיים) שה-hash שלו (SHA-256) שמור בטבלת הסשנים המאוחדת עם principal_type (ARC-01); אין JWT (BIZ-54).
הרשאות
כל בקשה עסקית מזוהה מהסשן בלבד: req.principal={type:'biz',userId,groupId,role,employeeRoleType}. groupId/userId אינם נקראים לעולם מ-body/query/params לצורך הרשאה (ARC-04). נתיבים ציבוריים — רק מרשימה סגורה מוצהרת (מילוי סקר לפי קוד, פנייה/צ'אט לקוח מחנות בטוקן storefront, /api/public/*, הצטרפות בקוד) (BIZ-02).
קלט ואימותים
  • חסר טוקן → 401 "נדרש token להתחברות עסקית".
  • hash לא נמצא / סשן מבוטל (revoked_at) → 401 "פגישה לא תקינה — יש להתחבר מחדש".
  • expires_at עבר → 401 "פגישה פגה — יש להתחבר מחדש" (תפוגה מתגלגלת 30 יום לפי last_seen, מקסימום 90 יום — ARC-09).
  • משתמש שאינו status='active' → 401; קבוצה frozen/archived → 403 "החשבון מוקפא" (ARC-05).
  • Guard סוג: נתיב BIZ מקבל רק principal_type='biz' → אחרת 403 "גישה מורשית לעסקים בלבד". verifyFamily מקבל רק סשן משפחתי (BIZ-13); נתיב המשרת שתי הסביבות מוצהר במפורש כ-verifyFamilyOrBiz (רשימה: /api/users/:id/permissions, /api/users/:id (DELETE), /api/users/:id/role-type, /api/users/:id/profile, /api/transaction (POST/PUT/DELETE), /api/transactions, /api/admin/*, /api/tasks*, /api/budget/*, /api/loans/*, /api/goals*, /api/academy/*, /api/support/ticket*, /api/group/members, /api/activity).
  • אין מסלול legacy: verifyBizOrLegacy וה-fallback ל-groupId מה-body בוטלו (ARC-03); בקשה ללא header לנתיב BIZ → 401.
  • Guard ADMIN (verifyBizAdminOnly) — לא ADMIN → 403 "פעולה זו דורשת הרשאת מנהל/ת עסק".
שלבי עיבוד
  1. חילוץ טוקן (עם/בלי "Bearer ").
  2. SELECT מטבלת הסשנים לפי hash + JOIN users (role, employee_role_type, status) + family_groups (account_status).
  3. בדיקות תפוגה, ביטול, סוג, סטטוס משתמש וחשבון.
  4. UPDATE last_seen (fire&forget).
  5. הצבת req.principal (וה-alias req.bizAuth לתאימות יומן הביקורת — רק לסשן biz).
