מטרה וטריגר
פונקציה אחת בשרת computeSlots(ctx, {date, practitionerId?, serviceId?}) (BTY-24) שמשרתת: מודאל "תור חדש" ביומן, בקשת תור בחנות (BTY-42), כרטיסי משבצות פנויות בתצוגת יום, ובדיקת זמינות של תור בודד (מצב check, שמחליף את GET /availability — BTY-03). מסלול: GET /api/beauty/:bizId/slots?practitionerId&date&serviceId.
הרשאות

קלט ואימותים
  • חסר date ⇒ 400 "חסר bizId או date" (ללא שינוי).
  • מטפלת לא קיימת בעסק או לא פעילה ⇒ slots:[].
  • אין מפתח ב-work_days ליום בשבוע (לפי Asia/Jerusalem, 0=ראשון) ⇒ יום חופש, slots:[].
  • serviceId: שירות פעיל של העסק; אם יש available_days והיום אינו בהם ⇒ []; אם allowed_practitioner_ids לא ריק והמטפלת אינה בו ⇒ [].
  • ללא practitionerId (חנות "ללא העדפה"): איחוד המשבצות של כל המטפלות הפעילות המורשות לשירות, עם רשימת מטפלות פנויות לכל משבצת.
שלבי עיבוד
  1. step = slot_minutes ?? 60; משך משבצת = duration_minutes של השירות אם הועבר serviceId, אחרת step (כמו היום).
  2. שעות עבודה: חיתוך של work_days[dow] (ברירת מחדל 09:00–18:00) עם available_days[dow] של השירות אם הוגדר. אם work_days הוא NULL או ללא מטפלת: שעות calendar_settings (open/close) של העסק אם קיימות, אחרת 09:00–18:00.
  3. אירוע calendar_events של העסק עם [ALL_DAY] ב-notes ביום המבוקש סוגר את היום (נשמר מהחנות היום).
  4. שליפת סגמנטים active של המטפלת באותו יום, של אותו עסק, שתורם אינו cancelled/no_show, ובקשות חנות pending שהמטפלת המועדפת בהן היא המטפלת (כחסימה רכה בחנות בלבד).
  5. לולאה מ-start בקפיצות step עד cur+dur <= end; משבצת נכללת אם slotStart > now ואין חפיפה בקטע חצי-פתוח !(slotEnd <= bs || slotStart >= be).
  6. תגובה: {success, slots:[{time:'HH:MM', start, end, practitioner_ids?}], slotMinutes}; start/end כ-ISO עם offset.
  7. מצב check (?check=1&start&duration&resourceId): מחזיר {available, conflicts:[{type:'practitioner'|'resource'|'rule', ...}]} לפי אותם כללים.

הרשאות

קלט ואימותים

שלבי עיבוד
  1. withTransaction (client אחד, release יחיד — ARC-11).
  2. UPDATE beauty_appointments SET status='completed' WHERE id AND business_group_id AND status='confirmed' RETURNING total_price, client_record_id, client_family_id; 0 שורות ⇒ 409.
  3. חומרים (BTY-35): הרשימה = materials מהבקשה, או ברירת המחדל של השירותים בסגמנטים (beauty_service_materials), או backbar_items בסגמנט. לכל פריט: UPDATE beauty_inventory SET stock_qty=stock_qty-qty WHERE … AND stock_qty>=qty; אם אין מספיק — לא חוסם: נרשם חוסר והתראת מלאי. כל ניכוי נרשם ב-beauty_inventory_movements (reason='usage', appointment_id).

  5. מימוש חבילה (BTY-49): אם נשלח redeem_subscription_id — מימוש כניסה (ראו "מכירת מנוי ומימוש") והתור מסומן payment_confirmed=true, payment_method='subscription' (לא נכנס לגבייה ולא נרשמת הכנסה נוספת).
