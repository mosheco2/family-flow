חישובים

שלבי עיבוד

  5. Polling חשבונות כל 4 שניות — מיזוג כקיים (submitted מהשרת גובר; pending מקומי רק לשולחן הנבחר; שולחן שנמחק בשרת נמחק).

  7. "×" על פריט שנשלח (RST-11): מנהל משמרת → POST /api/store/orders/:id/items/:itemId/void {reason} — בטרנזקציה: השורה ב-store_order_items מסומנת voided_at, voided_by, void_reason, total_amount מחושב מחדש, הפריט מוסר מ-items_ready, audit VOID_ORDER_ITEM. משתמש אחר → POST …/void-request {reason} (void_status='requested'), הפריט מסומן "ממתין לאישור ביטול"; מנהל משמרת מאשר (→ void כנ"ל) או דוחה. שולחן שכל פריטיו בוטלו ואין pending — החשבון נמחק (כקיים).
חישובים
"חדש לשליחה" = Σprice×qty של pending; סה"כ חשבון לא כולל פריטים שבוטלו; כפתור ראשי → "💳 סגור חשבון" כשאין pending וכל ה-submitted (שלא בוטלו) סופקו — כקיים.
מכונת מצבים

תופעות לוואי

ממשק
