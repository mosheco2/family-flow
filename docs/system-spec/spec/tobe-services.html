פקודות עבודה / תיקים (Work Orders)

המרת הצעת מחיר לפקודת עבודה / תיק

מטרה וטריגר
בעל עסק (BIZ) הופך הצעת מחיר (store_orders בסטטוס quote) לפקודת עבודה. שתי נקודות הכניסה בממשק נשמרות: (א) כפתור "🔨 המר לפקודת עבודה / לתיק" (business-app.js:42690 convertToWorkOrder, wrapper 9531 convertQuoteToWorkOrder); (ב) אישור הצעה עם תאריך יעד במודל "יעד אספקה" (business-app.js:9649 submitTargetDatetime). שתיהן קוראות לנתיב שרת יחיד POST /api/work-orders/convert/:quoteId עם target_datetime אופציונלי. פקודת העבודה נשארת אותה שורה ב-store_orders (id זהה), מסומנת call_type='work_order'.
הרשאות
סשן BIZ בלבד (ARC-01/ARC-03: אין עוד verifyBizOrLegacy); groupId מהסשן (ARC-04); זכאות למודול sales (ARC-17). ההצעה חייבת להיות של העסק: WHERE id=$1 AND group_id=principal.groupId.
קלט ואימותים
  • quoteId בנתיב; גוף אופציונלי: target_datetime (ISO, Asia/Jerusalem), title.
  • הצעה לא נמצאה/לא של העסק → 404 "הצעה לא נמצאה".
  • הצעה שכבר הומרה (call_type='work_order') → 409 "ההצעה כבר הומרה לפקודת עבודה".
  • ממשק: אישור _uiConfirm עם נוסח שונה לעסק professional ("להמיר הצעה זו לתיק?") (42691-42695) — ללא שינוי.
שלבי עיבוד
  1. טרנזקציה אחת (withTransaction, ARC-11), נעילת שורת ההצעה FOR UPDATE. כוללת גם את תופעות הלוואי מ-/approve (tobe-store, STR-29): upsert לקוח (STR-42) ו-business_id מ-metadata.companyId אם הוא של העסק. created_at לא נדרס.
  2. חילוץ כותרת: title מהגוף, אחרת quote_title, אחרת מפריט metadata (is_quote_metadata → JSON data.title/notes), ברירת מחדל "פקודת עבודה — <לקוח|מס' הצעה|#id>" (הלוגיקה של 15094-15105 נשמרת).
  3. UPDATE store_orders SET call_type='work_order', quote_status='approved', quote_title=…, status='processing', target_datetime=COALESCE($t, target_datetime).
  4. הוספת אירוע {type:'converted_to_work_order',actor:'business',at} ל-quote_history (jsonb append).
